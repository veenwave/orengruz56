# ОренГруз — коммерческий шаблон (мульти-клиентская версия)

Это комплект статического сайта + защищённой панели владельца. Его можно тиражировать для разных компаний: исходный код общий, данные каждой компании хранятся отдельно в Supabase.

## Что входит

- `index.html` — публичный сайт с адаптивной мобильной вёрсткой, калькулятором материалов, расчётом доставки, формой заявки и переходом в MAX/Telegram.
- `admin.html` — отдельная панель владельца с входом по email и паролю, возможностью сменить пароль.
- `site-config.js` — единственный файл настройки конкретной компании. Разработчик меняет название, телефон, город, ссылки на мессенджеры и tenant slug.
- `app.js`, `admin.js`, `supabase-client.js`, `styles.css` — логика сайта, админки и оформление.
- `supabase/schema.sql` — схема базы данных, RLS-политики, правила хранилища и стартовые записи для ОренГруз56.
- `assets/` — исходные фотографии-заглушки из старого шаблона.

## Архитектура

Surge.sh размещает статические файлы и не запускает серверный код, функции или базу данных. Поэтому сайт размещается на Surge, а авторизация, общая база и фотографии — в одном проекте Supabase. Один общий проект Supabase обслуживает несколько компаний.

Каждый клиент получает отдельную статическую публикацию с теми же файлами, но своим `tenantSlug` в `site-config.js`. Например:

- `orengruz56` — ОренГруз56;
- `kamaz-arenda` — другая компания;
- `stroytehnika-56` — третья компания.

Все данные связаны с `tenant_slug`. Row Level Security (RLS) разрешает владельцу изменять только строки компаний, к которым его учётная запись добавлена в `tenant_memberships`.

## Важные правила безопасности

1. В браузер можно помещать только Supabase Project URL и Publishable/anon key. Такой ключ публичный по назначению: защита обеспечивается RLS и правами таблиц.
2. Никогда не добавляйте в `site-config.js`, HTML или JS `service_role` / secret key, пароли владельцев, Bot Token Telegram или секреты MAX.
3. В Supabase выключите публичную регистрацию пользователей. Создавайте владельцам учётные записи вручную и отдельно добавляйте их UUID в `tenant_memberships`.
4. Не выдавайте владельцам доступ к Supabase Dashboard. Им нужна только панель `/admin.html`.
5. Держите резервные копии SQL/данных и следите за использованием Supabase Storage и Database.
6. Публичный сайт показывает цены и материалы. Посетитель может их читать, но не изменять. Публичный доступ к фото открыт по назначению; запись/удаление файлов разрешены только члену соответствующей компании.

## Первичная настройка (делается один раз)

1. Создайте проект в Supabase. Выберите регион ближе к основной аудитории, если доступен и подходит по требованиям.
2. В Supabase откройте **SQL Editor** и выполните весь файл `supabase/schema.sql`.
3. В Supabase откройте **Project Settings → API** (или API Keys) и скопируйте Project URL и Publishable key. Внесите их в `site-config.js` вместо `YOUR_PROJECT_REF` и `YOUR_SUPABASE_PUBLISHABLE_KEY`.
4. В Supabase откройте **Authentication → Providers / Sign In**, отключите публичную регистрацию (Allow new users to sign up).
5. В **Authentication → Users** создайте владельца вручную (email + временный пароль или invite). Скопируйте UUID созданного пользователя.
6. Вернитесь в SQL Editor и выполните, подставив реальный UUID:

```sql
insert into public.tenant_memberships (tenant_slug, user_id, role)
values ('orengruz56', 'UUID-ПОЛЬЗОВАТЕЛЯ-ИЗ-AUTH-USERS', 'owner');
```

7. Откройте `/admin.html`, войдите по учётным данным владельца, попросите его сразу сменить временный пароль в блоке «Безопасность аккаунта». Проверьте добавление/редактирование материала, загрузку фото, районы и тарифы. Проверьте публичную страницу в другом браузере/режиме инкогнито.

## Настройка нового клиента

Для каждой новой компании:

1. Скопируйте папку проекта в новую папку публикации.
2. В `site-config.js` измените `tenantSlug` на уникальный латинский slug (3–50 символов, только `a-z`, `0-9` и дефис), название, телефон, город, тексты и ссылки мессенджеров. Оставьте те же Supabase URL и Publishable key.
3. Откройте `supabase/provision_tenant_template.sql`, замените `new-company` на slug нового клиента и выполните скрипт в SQL Editor. Он создаст компанию, стартовый каталог, технику и районы. Если у клиента другие материалы — владелец поменяет их в админ-панели.
4. Создайте владельцу отдельного пользователя в Supabase Auth и добавьте его UUID:

```sql
insert into public.tenant_memberships (tenant_slug, user_id, role)
values ('novaya-kompaniya', 'UUID-ПОЛЬЗОВАТЕЛЯ', 'owner');
```

5. Опубликуйте эту папку на отдельном Surge-домене или домене заказчика.

Один и тот же пользователь может быть добавлен только к нескольким компаниям, если это действительно нужно. Для обычного клиента выдавайте доступ только к его slug.

## Публикация на Surge

Surge использует командную строку. Из папки конкретного сайта:

```bash
npm install --global surge
surge . имя-клиента.surge.sh
```

Для повторного обновления — та же команда с тем же доменом. Для собственного домена его DNS нужно настроить по инструкциям Surge. Не храните Surge token в публичном репозитории.

## Что может менять владелец

- Добавлять, изменять и удалять материалы.
- Менять цену за тонну и плотность материала.
- Загружать новые фотографии материалов.
- Добавлять и менять технику, её грузоподъёмность и тарифную категорию.
- Загружать фотографии техники.
- Менять стоимость доставки по районам для малого, среднего и большого самосвала.
- Добавлять и удалять районы доставки (последний оставшийся район удалить нельзя).
- Временно скрывать материалы и технику с публичного сайта.
- Самостоятельно менять пароль своей учётной записи в панели.

## Что меняет разработчик в `site-config.js`

Название компании, номер телефона, город, заголовок/описание, ссылки на MAX и Telegram, уникальный slug и параметры Supabase. Эти поля намеренно не находятся в панели владельца. Файл находится рядом с `index.html`, `admin.html` и остальными файлами сайта. Для нового клиента редактируется только его копия `site-config.js`.

## Модель обслуживания нескольких клиентов

- Ты владеешь общей Supabase-организацией и проектом, в котором находятся данные всех компаний. Не передавай клиентам доступ к этому проекту.
- У каждого сайта — свой `tenantSlug`, публикация Surge и учётная запись владельца. Владелец видит только каталог, технику и районы своего `tenantSlug`.
- Это не отдельная новая база на каждого покупателя: клиенты разделены политиками RLS внутри общей базы.
- Если ты обновишь общие файлы шаблона, уже опубликованные копии клиентов нужно будет обновить повторной публикацией на Surge.
- Владелец получает доступ к панели `/admin.html`; данные, доступ и работу общей базы продолжаешь обслуживать ты. Это стоит учитывать в цене и договорённостях по поддержке.
- Для реального коммерческого использования заранее проверь тариф Supabase и порядок оплаты из своего региона. Бесплатные проекты могут приостанавливаться после недели низкой активности; платные планы не приостанавливаются за неактивность.

## Ограничения текущей версии

- Отправка заявки пока работает как подготовка текста, копирование и открытие MAX/Telegram. Для MAX и Telegram нужно прописать реальные ссылки компании в `site-config.js`; кнопки обоих каналов по умолчанию показываются. Сайт не утверждает, что заявка автоматически доставлена или сохранена в CRM.
- История заявок, автоматическая отправка через бота, SMS-коды, онлайн-оплата и CRM требуют отдельной серверной логики (например Supabase Edge Function) и не входят в этот комплект.
- В текущей версии клиентская антиспам-проверка не заменяет серверный rate limit.
- Владелец может менять каталог и тарифы, но не может менять брендовые контакты из панели; это сделано намеренно.
- Тесты исходников не заменяют реальные проверки на телефонах, браузерах и в развёрнутой базе.
